# 矿权日报 Agent

按 MCP 协议取数、用 LangGraph 编排的矿业分析助手。

输入「给我生成一份关于 Pilbara 锂矿的今日简报」，它会自己检索新闻、下载年报抽储量表、
查行情，然后输出一份带出处引用的 Markdown 简报。

3 个 MCP server（FastMCP 封装）+ 1 个 Agent 客户端（LangGraph）+ 1 个网页。

**怎么跑：[RUN.md](RUN.md)**

## 一、Graph 介绍

```mermaid
flowchart LR
    S([START]) --> I[intent]
    I --> A[agent]
    A -->|有 tool_calls| T[tools]
    T --> A
    A -->|无 tool_calls| E([END])
```

三个节点，代码在 [agent.py](agent.py) 的 `build_graph()`。

### `intent` —— 判断意图 + 改写输入

用模型看最近几轮对话和用户最新一句话，只输出一个 JSON：

```json
{"needs_data": true, "rewritten": "铁矿石目前的价格是多少"}
```

- **`needs_data`**：这句需要外部数据吗？要价格 / 新闻 / 储量 / 简报 → `true`；
  打招呼、闲聊、问能力、让解释概念 → `false`
- **`rewritten`**：把这句话改写成**自包含的请求** —— 指代词还原、省略补全

**为什么单独拆一个节点**：最早只有 `agent` + `tools`。实测发现模型在连续对话里会被上文带偏 ——
上一轮问过铁矿石走势，这一轮只说「你好」，它又去调了一遍 `get_trend(铁矿石)`；连说三次「你好」
就连调三次。**光在系统提示里写「打招呼别调工具」压不住**，因为问题出在对上文的理解，
不是它不知道规则。所以拆出来先判一次意图。

改写那一半也真的有用：上文问过碳酸锂，这轮只说「它今年最低多少」，「它」会被正确还原成「碳酸锂」。
单靠 `agent` 只能猜。

三个实现细节：

- 判断结果**不写进 `messages`**（自定义的 `AgentState` 比 `MessagesState` 多两个字段），
  只在 `agent` 节点里临时替换最后一条用户消息 —— 否则每轮都会往历史里塞一条内部消息
- 明确是纯问候（`你好` / `谢谢` / `hi`，整句就是问候才算）走正则短路，不再花一次模型调用。
  「你好，顺便查下铜价」不会被误判
- 判不出来时一律按 `needs_data=true` 走：宁可多调一次工具，也不要因为误判成闲聊而答不出
  用户真正要的东西

### `agent` —— 调模型

按 `needs_data` 选模型：为 `true` 时用**绑定了工具**的模型，为 `false` 时用**裸模型**。
寒暄那类从机制上就不可能发起工具调用，不是靠提示词求它自觉。

这里还兜住了一个「整轮对话直接死掉」的坑：模型把数组参数写成字符串时，pydantic 校验失败
发生在**响应解析阶段**（还没进 `ToolNode`），`ToolNode.handle_tool_errors` 兜不住 ——
整轮会直接结束、连回答都没有。所以失败时带一句纠正提示重试一次；**再失败就原样抛出原始异常**，
不再包装成「工具参数解析失败」（早先这么包过，把密钥错误、网络不通全盖成同一句话，
排查时被结结实实带偏过）。

### `tools` —— 执行工具

LangGraph 的 `ToolNode`。工具在**启动时**从 3 个 MCP server 一次性加载。

### 工具怎么从 MCP 到 LangGraph

用 FastMCP 的 `Client` 把 3 个 server 拉起来，`list_tools()` 拿到 9 个工具，
再逐个包成 LangChain 的 `StructuredTool`（[agent.py](agent.py) 的 `make_tool()`）——
用 MCP 的 `input_schema` 动态生成 pydantic 模型当 `args_schema`。

工具名是 FastMCP 给的 `{server}_{tool}`（如 `lme-price_get_price`），
这个格式本来就是合法的 OpenAI 函数名，不需要改写。

两个必须处理的细节：

- **`Annotated[X | None, Field(...)]` 生成的是 `{"anyOf": [...]}`、没有顶层 `type`**。
  直接 `spec.get("type", "string")` 会拿到默认值 `"string"`，把所有可选参数一律声明成字符串 ——
  数组参数因此会被拒（`Input should be a valid list`）。所以有 `_json_type_of()` 专门解析 `anyOf`
- 数组类型放宽成 `list | str`，并在 wrapper 里把 `"A,B"` 归一化成 `["A","B"]`。放宽 schema
  比打断整轮划算

> ⚠️ **为什么不用官方的 `langchain-mcp-adapters`**：它要求 `mcp<2.0.0`，而 fastmcp 4 要求
> `mcp>=2.0.0`，两者**硬冲突**。工具转换只能手写。

## 二、三个 MCP server

都用 **FastMCP** 封装，都**不调用 LLM、不依赖外部服务**（没有向量库、没有嵌入模型），
唯一的运行时状态是一个 SQLite 文件加一个 HTTP 缓存目录。所以每一个都能**单独挂进
Claude Desktop / Cursor 跑起来**，也可以只挂其中一个。

### `mining-news` — 矿业新闻 · [news_server.py](news_server.py)

| 工具 | 签名 | 作用 |
|---|---|---|
| `search` | `(query, days=30, limit=15, live=True)` | 检索近 N 天新闻；本地召回不足时自动按查询补抓 |
| `fetch_article` | `(url)` | 抓单篇正文 |
| `corpus_stats` | `()` | 本地库规模与时间跨度（诊断用） |

两条互补通道：**常驻 RSS**（mining.com、The Northern Miner，翻页可回溯数年）+
**按查询实时抓 Google News**（中英各一路）。

### `mineral-pdf` — 技术报告储量抽取 · [pdf_server.py](pdf_server.py)

| 工具 | 签名 | 作用 |
|---|---|---|
| `extract_resources` | `(pdf_url, categories=None, max_pages=None)` | 从 NI 43-101 / JORC 报告抽 Indicated / Inferred 储量表 |
| `known_reports` | `(company=None)` | 查已登记的报告索引 |

抽出来的是矿石量（Mt）、品位（g/t 或 %）、金属量（oz 或 t）。

### `lme-price` — 价格行情 · [price_server.py](price_server.py)

| 工具 | 签名 | 作用 |
|---|---|---|
| `get_price` | `(commodity, date=None, verify=False)` | 某品种价格，可传历史日期 |
| `get_trend` | `(commodity, days=30)` | 近 N 日走势 + 区间统计 |
| `list_commodities` | `()` | 可查的品种（8 个）及其别名 |
| `list_sources` | `()` | 数据源及其权威性等级 |

覆盖上期所（沪铜 / 沪锌 / 沪镍）、广期所（碳酸锂）、LME（伦铜 / 伦锌 / 伦镍）、
大商所（铁矿石）。

> 题面把锂写成「SHFE 锂」有误 —— 碳酸锂期货在**广州期货交易所（GFEX）**，上期所没有锂品种。
> 品种表里保留 `SHFE 锂` 作别名，照题面原话提问也能命中。

## 三、Agent 当前能力

### 能做什么

| 能力 | 怎么问 | 会调到 |
|---|---|---|
| **查新闻** | 「最近有什么 Pilbara 的新闻」「近 7 天锂矿相关报道」 | `mining-news_search` |
| **读正文** | 「把第一篇的正文给我」 | `mining-news_fetch_article` |
| **抽储量** | 「Pilbara 的资源量是多少」 | `mineral-pdf_known_reports` → `mineral-pdf_extract_resources` |
| **查价格** | 「碳酸锂现在多少钱」「9 月 30 日沪铜收盘价」 | `lme-price_get_price` |
| **看走势** | 「铁矿石近 30 天走势」「它今年最低多少」 | `lme-price_get_trend` |
| **出简报** | 「给我一份 Pilbara 锂矿的今日简报」 | 上面几个组合，输出固定结构的 Markdown |
| **问元信息** | 「你能查哪些品种」「你这些数据从哪来的」 | `lme-price_list_commodities` / `list_sources` |

多轮对话是保留上下文的：「碳酸锂多少钱」→「那它今年最低多少」，第二句的「它」由 `intent`
节点还原成碳酸锂再交给 `agent`。

### 出简报时的固定结构

用户要「简报 / 日报」时，输出**必须**是这个结构，不许另起一套小节名：

```
# 矿权日报 · <对象> · <日期>

## 一、新闻摘要      3-5 条，每条一句话 + 来源
## 二、储量数据
## 三、价格走势
## 四、风险提示
## 引用来源          编号列出所有用到的链接
```

四节**每一节都要有**。拿不到就在那一节里写明「本次未取得」和原因，**绝不许悄悄跳过整节**。

### 做不到 / 边界在哪

- **品种只有 8 个**：上期所三个、广期所一个、LME 三个、大商所一个。问别的品种会返回
  `unknown_commodity` 并附上可查清单，不瞎猜
- **储量报告是人工白名单**：`known_reports` 目前只登记了 Pilbara 与 Implats 两份。
  没登记的会明确说没有，不会拿正文里的数字凑
- **LME 只能走转载源**（官网 403 地域封锁，官方行情需购买授权）
- **铁矿石是期货口径**，不是题面点名的上海钢联现货指数（见第四节）
- **Google News 的聚合链接抓不到正文**，只有标题摘要，这类条目不会拿去冒充全文

### 一条贯穿所有回答的纪律：拿不到就说拿不到

- 正文抓不到 → `full_text_unavailable` + 原因
- 储量表识别不出 → `no_table_found` + 原因，不返回半成品
- 推算的金属量放 `contained_derived` 字段，**与抽取值分开**
- 每个数字都带 `source_tier`，说明这个数从哪来、该信几分

## 四、数据查询方式介绍

以「**铁矿石现在多少钱**」为例走一遍。这句话会经过四个阶段。

### 第 1 步：判断意图

`intent` 节点把问题 + 最近几轮对话交给模型，拿到：

```json
{"needs_data": true, "rewritten": "铁矿石目前的价格是多少"}
```

`needs_data=true` 意味着后面要走绑定了工具的模型。如果用户只是说「你好」，
这里就是 `false`，后面直接走裸模型，一个工具都不会调。

### 第 2 步：进入 agent 节点

`agent` 节点把**改写后的那句话**连同 9 个工具的 schema 一起发给模型。模型看到有个
`lme-price_get_price(commodity, date, verify)`，于是决定调用它：

```json
{"name": "lme-price_get_price", "args": {"commodity": "铁矿石"}}
```

到这一步为止，模型**只知道品种名是「铁矿石」**，完全不知道去哪个网站、取哪个合约、
按什么单位换算。下面这一步才是真正找数据的地方。

### 第 3 步：调用工具，返回 agent ⭐

`get_price` 在 [price_server.py](price_server.py) 里，内部是一条五跳的链路。

**3.1 把「铁矿石」解析成品种** —— `resolve()`

品种表 `COMMODITIES` 登记了 8 个品种，每个带 `key` / 中文名 / 英文名 / 别名数组。
启动时全部小写铺进 `_ALIAS_INDEX` 做查表。`铁矿石` 这条的登记长这样：

```python
"dce_iron_ore": {
    "name_zh": "铁矿石", "name_en": "Iron Ore", "exchange": "DCE",
    "secid": "114.i2610",                    # 主力的行情代码
    "unit": "CNY/t", "currency": "CNY",
    "rollable": ["114.i{yy}{mm}"],           # 换月时按月份向后试探
    "aliases": ["铁矿石", "铁矿", "铁", "iron ore", "ironore", "i", "普氏"],
}
```

`resolve()` 三级匹配：**精确命中** → **去空格后命中** → **最长别名子串**
（第三级是为了「今天的铁矿石价格」这种带修饰词的说法）。
命中 `dce_iron_ore`，拿到 `secid = 114.i2610`。认不出就返回 `unknown_commodity` + 可查清单，
**不猜**。

**3.2 决定用哪个源** —— 查 `OFFICIAL_CODES`

这张表只登记了四个品种：上期所的沪铜 / 沪镍 / 沪锌、广期所的碳酸锂。
**铁矿石不在里面** —— 大商所官网的日行情导出接口实测返回 412（反爬前置检查），
没有可用的官方源。所以铁矿石跳过「官方直连」，直接落到转载源阶梯。

**3.3 取数** —— 东财 push2 实时接口

```
GET https://push2.eastmoney.com/api/qt/stock/get?secid=114.i2610&fields=f43,f44,f45,...
    Referer: https://quote.eastmoney.com/     ← 不带会被部分节点拒绝
```

超时 8 秒、缓存 TTL 120 秒、失败允许回退到过期缓存（会标 `stale` —— 宁可用一份标了
「已过期」的旧价，也不让整份简报因为一次取价失败而中断，但**必须标出来**）。

**3.4 解析与单位换算** —— 这一步最容易出错

东财返回的是**整数化报价**：`f43 = 6835`。它不是 6835 元/吨，而是 683.5 元/吨 ——
铁矿石这个品种报价精确到 0.1 元，接口把小数位抹掉了。所以要先看返回体里的 `f59`
（小数位数）；缺失时退回品种表里的经验值 `price_scale()`：**代码以 `i` 开头的除以 10**。

`6835 / 10 = 683.5 CNY/t` ✔

这条经验值是实测出来的（LME 铜、沪镍都是 1:1，只有铁矿石是 1:10），
不换算的话会得到一个**大十倍、但看起来完全正常**的数字。

**3.5 取不到时的降级链**

```
东财实时报价  ──失败──►  按换月模板试探 114.i2611 / 2612 / 2701
                             ──失败──►  新浪财经 nf_I0 作第二源
                                            ──失败──►  日线收盘价兜底（300 根，固定长度）
                                                           ──仍无──► no_price_data + 原因
```

换月试探是必要的：配置里写死的 `114.i2610` 是当时的主力，主力换月后实时接口就没数据了。

日线请求**固定取 300 根再本地切片** —— 早先按需要的长度请求，于是 `lmt=30` 和 `lmt=45`
是两个不同的 URL、两个不同的缓存项，同一份数据反复回源，既慢又更容易撞上东财的限流。

**3.6 组装返回体**

```json
{
  "commodity": "dce_iron_ore",
  "name_zh": "铁矿石",
  "exchange": "DCE",
  "unit": "CNY/t",
  "date": "2026-10-08",
  "price": 685.0,
  "day_range": [683.0, 687.0],
  "is_realtime": true,
  "note": "东方财富实时接口对该品种无数据，已改用新浪财经备用源",
  "source": "新浪财经 hq.sinajs.cn (nf_I0)",
  "source_key": "dce_iron_ore_futures",
  "source_tier": "substitute",
  "source_note": "来源：大连商品交易所 铁矿石期货（替代口径，与原口径不等价，请留意）"
}
```

（上面这份是实跑的真实返回，恰好走了降级链的第二跳：东财实时接口对铁矿石返回空，
自动落到了新浪。`note` 字段把这件事记了下来。）

`source_tier` 是**每个返回值都带**的字段，含义见下表。同一句「685 元/吨」，
从交易所官网取的和从行情门户取到的，可信度不一样，不标出来读的人无法判断该信几分。

| 等级 | 含义 |
|---|---|
| `official` | 交易所 / 公司官网一手数据，可直接引用 |
| `relay` | 门户转载的官方行情，数值通常一致但可能滞后 |
| `substitute` | 用相近但**不同**的东西顶替，**不等价** |

**关于铁矿石，有一件事必须说清楚**：题面点名的是**上海钢联的铁矿石现货指数**，
实测拿不到（指数接口返回 401「认证参数传入不完整」，需签名认证与订阅；免费接口只给资讯
不给指数值）。所以这里给的是**大商所铁矿石期货**的价格。

期货和现货指数**不是一回事** —— 期货含基差、含预期，跟现货指数不能互相替代引用。
所以铁矿石的返回值标的是 `substitute` 而**不是** `relay`：`source_tier` 描述的是
**这个数是不是用户要的那个东西**，跟它经哪个门户取到无关。铁矿石走东财、走新浪、
还是走日线兜底，标的一律是 `substitute` —— 口径的差异盖过后端的来源差异。

| 品种 | source_key | source_tier |
|---|---|---|
| 沪铜 / 沪锌 / 沪镍 | `shfe_official` | `official` |
| 碳酸锂 | `gfex_official` | `official` |
| LME 铜锌镍 | `eastmoney` / `sina_finance` | `relay` |
| **铁矿石** | `dce_iron_ore_futures` | **`substitute`** |

### 第 4 步：输出答案

工具结果回到 `agent` 节点，模型基于返回体给出回答，并在每个数字后面标明出处：

```
铁矿石 685.0 元/吨，当日区间 683.0 – 687.0 元/吨（大商所铁矿石期货，新浪财经行情）。

注：这是大商所期货价格，不是上海钢联的现货指数 —— 两者口径不同，不能直接互换引用。
```

`route()` 检查最后一条消息有没有 `tool_calls`：没有就结束这一轮；如果模型还想再查
（比如顺带问一句「那今年走势呢」），就再回到 `tools`，直到不再调工具为止。

### 附：新闻和储量的查询方式

另两个 server 的取数逻辑不一样，简述：

**新闻**走四级召回阶梯 —— 精确召回（AND + 中英术语扩展）→ 本地不足时按查询实时抓
Google News → 再精确召回 → 才降级到宽松召回（OR，标 `low_confidence`）。
**补抓必须在宽松召回之前**：先宽松召回的话，OR 凑出的几条弱相关结果会让上游误以为
「已经召回充分」，从而跳过真正该取的数据源。入库还有两道去重（URL + 归一化标题）——
同一条报道在 Google News 中英两路、或媒体 RSS 与聚合源之间 **URL 是不同的**，
实测 592 篇里有 22 组同标题重复。

**储量**不用 pdfplumber 的 `extract_tables()`：实测无框线的报告返回 0 张表，
有框线的检测到了但标签列被丢掉。改成按坐标重建 —— 词按纵坐标聚成行 → 找含
`Tonnes` + `Grade` 的表头行 → **把这些行里数字的横坐标聚类成列** → 每列取横向邻近的表头词
判定语义与单位。第三步是关键：真实报告里表头词挨得极近（Pilbara 相邻列中心只差 40pt），
按表头词间距合并会糊成一团，按数据数字的横坐标分列则天然分开。

四种方式，以及换模型供应商、目录结构、踩过的坑。

两种入口：

| 入口 | 命令 | 说明 |
|---|---|---|
| 网页 | `python web.py` → `localhost:8000` | 左边对话、右边数据预览（简报 / 新闻库 / 价格 / 数据源） |
| 命令行 | `python agent.py` | 交互式聊天，每次工具调用和返回都会打印 |

API Key 可以直接在网页上填，不需要 `.env`。
